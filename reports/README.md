# reports/ —— 自检报告与截图样例

这个目录放的是**样例**，供文档引用（`docs/开发记录.md` §8.7、`docs/Windows构建与联调.md`  
会直接引它们），也是「报告长什么样」的参考。

| 文件                 | 是什么                                   | 怎么再生成一次                                             |
| ------------------ | ------------------------------------- | --------------------------------------------------- |
| `示例-本机边缘自检.txt`    | 服务器侧自检（四条边 + 按键 + 滚轮）的报告原文            | `NetMouse --hwtest --out reports/示例-本机边缘自检.txt`     |
| `示例-本机注入自检.txt`    | 客户端侧自检（本机能否驱动光标/按键/滚轮）的报告原文           | `NetMouse --injecttest --out reports/示例-本机注入自检.txt` |
| `示例-设置界面-平台拆分.png` | 设置界面的「本机平台卡片 + Windows/Linux 差异对照表」截图 | 打开界面截图即可                                            |

> **这些是构建机上跑出来的样例**（Windows，1280x800 单屏），不是你两台机器的报告。  
> 它们的作用是让文档里那句「报告里会打印 …」有据可查，**不要拿它们当诊断结论**。

## 你自己跑出来的报告在哪

真正的诊断报告写在**配置文件旁边**（见 README「配置文件的存放位置」），  
而不是这个目录：

- `diag` 报告 —— 托盘菜单「运行诊断…」跑完会自动打开；
- `--hwtest` / `--injecttest` —— 不指定 `--out` 时写进配置文件同目录，  
  终端里最后一行会打印完整路径。

命令行想直接指定位置就加 `--out`：

```bash
NetMouse --injecttest --out /tmp/nm-inject.txt      # Windows: NetMouse.exe --injecttest --out D:\nm.txt
```

**把报告发回来排查时，请连同两台机器的报告一起发** —— 单看一台分不清是  
「本机没发出去」还是「对端没注入成功」（原因见 README 的「本机自检」一节）。
